# Проверки качества

- После изменения кода запускай проверки затронутой части проекта.
- Перед завершением задачи запускай относящиеся к ней проверки линтера,
  форматирования и сборки. Для frontend это ESLint, Prettier и Vite;
  для Python — Ruff check и Ruff format --check. Отдельной сборки Python нет.
- Команды установки и запуска находятся в README.md; правила — в pyproject.toml,
  frontend/eslint.config.mjs, .prettierrc.json и .prettierignore.
- Обычные проверки не должны менять исходники. Исправления запускай отдельно,
  только в пределах задачи; небезопасные автоисправления автоматически не применяй.
- Не отключай правила ради прохождения проверок.
- Не исправляй посторонние файлы без необходимости; не форматируй весь проект
  при локальной правке. Не трогай пользовательские данные и секреты.
- Отличай существовавшие ошибки от внесённых изменениями. Сравнивай диагностику
  до и после правки; не объявляй проверку пройденной при оставшихся ошибках.
- Если проверка не выполнена, явно сообщай об этом и причине.
- Проектный скилл диагностики и исправления:
  [.agents/skills/code-quality/SKILL.md](.agents/skills/code-quality/SKILL.md).
